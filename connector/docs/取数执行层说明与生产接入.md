# 取数执行层说明与生产接入

本文说明 `umodel-assistant-py` 现有代码做了什么、正式使用时如何接入，以及哪些能力仍需企业侧完成。开源仓库已经提供什么、哪些必须自行建设，见 [《UModel 开源范围与自行建设说明》](UModel开源范围与自行建设说明.md)。

审阅所依据的开源版本为 `alibaba/UnifiedModel` 提交 `f065a68c51268c60be941180934462161f89f483`。本目录不重写该仓库的对象图、SPL 和官方 MCP。

## 1. 职责

开源 UModel 负责语义模型和对象图，并把部分查询编译成下游计划。`mode=data` 在开源服务中返回 `NOT_IMPLEMENTED`，错误信息指向仓库外的 `umodel-assistant`。本目录是这一层的 Python 实现：Agent 只调用一个工具，由本进程向真实存储取数后返回行。

Agent 不编写 SQL，不提交数据库地址或密码，也不能在工具参数里声明自己的身份。新业务系统通过增加模型 YAML 接入，不在代码里为单个系统写分支。

## 2. 现有代码做了什么

入口是 `mcp_server.py`。对外工具保持 `query_spl_execute`，另有 `query_spl_explain` 和 `query_spl_examples`。进程通过标准输入输出接入 Agent，不监听端口。

`query_spl_execute` 每次都先请求开源 Query Service，且只发送 `mode=plan`、`format=agent`、`include_spec=true`。`/explain` 不参与分发，因为其返回结构里没有存储位置。随后按回包处理：

1. 回包已是 `.umodel`、`.entity`、`.topo` 或 `list_*` 的行：确认调用方后返回。这类结果来自 Go 已加载的对象图。
2. 回包是 `prometheus_promql`、`elasticsearch_dsl` 或 `clickhouse_sql`：使用计划中的地址执行。没有地址则失败。
3. 计划只有存储类型、没有 SQL、PromQL 或 DSL：失败。不会把这类 ClickHouse 计划送进 MySQL。
4. Go 对不带 entity-call 的 `.entity_set` 返回 `QUERY_PLAN_ERROR`，且说明为 `requires entity-call`：按本目录 `model/` 里的 `data_link`、`storage_link` 和 `fields_mapping` 生成参数化 SQL 或 HTTP 请求。同一对象有多条 `data_link` 时，只采用目标名等于对象名、或以「对象名.」开头的那一条；仍不唯一则报错。一个数据集必须只有一条 `storage_link`。

`mode=plan` 只返回计划。`mode=data` 才连接存储，并在返回前按模型声明的字段投影、按字段标签脱敏、写入审计日志。

`model/` 由 Python 在启动时直接读取。其中的 commerce 文件是格式示例，包含用户、订单和支付。字段上的 `example`（如「张三」「O-2001」「P-3001」）不会被当作查询结果。业务对象查询不依赖把这批 YAML 导入 Go。导入只影响 Go 自己的对象图：`--quickstart` 装入的是开源示例，不是本目录的 commerce。要在 `.umodel`、`.entity`、`.topo` 中看到这些对象，才需要另行导入，见第 4 节。

Go 未启动时调用失败，本进程不会跳过 Go、直接查库。

### 已实现

| 能力 | 现状 |
|---|---|
| 开源计划客户端，固定 `mode=plan` 且 `include_spec=true` | 已实现。回包归一化为行、计划或错误 |
| 对象图和 `list_*` 结果转发 | 已实现 |
| PromQL、Elasticsearch、`clickhouse_sql` 执行 | 已实现。ClickHouse 当前按文本行返回，未解析为 `JSONEachRow` |
| MySQL、HTTP 的业务对象取数 | 已实现。SQL 使用绑定参数；HTTP 仅 GET |
| 只读 SQL 检查、出站 URL 白名单 | 已实现。拒绝多语句、写操作、注释；拒绝云元数据地址和链路本地地址。回环地址必须写成 `主机:端口` |
| 密钥引用 | 已实现环境变量。模型只保存 `secret://名字`，名字即变量名 |
| 字段投影与脱敏 | 已实现。只处理带 `tags.classification` 的字段：`pii.name`、`pii.phone`、`pii.email`、`pii.id_card` |
| 审计 | 已实现。结构化日志写到本进程 stderr，可用 `ENABLE_AUDIT_LOG=0` 关闭 |
| 调用方身份 | 已实现开发模式。默认拒绝；见第 5 节 |
| 自动化测试 | `tests/test_enterprise.py`。MySQL 使用注入的执行函数，HTTP 使用进程内接口，不代表已连接生产库 |

缺配置、未知方言、空壳计划或密钥不存在时返回错误，不返回空列表、假密码或示例行。`python mcp_server.py --self-test` 只检查订单 SQL 是否把 `U-1001` 放进参数，不连接 Go，也不返回样例数据。

## 3. 一次业务查询

Agent 需把自然语言转成 SPL，再调用 `query_spl_execute`。订单示例：

```text
.entity_set with(domain='commerce', name='commerce.order', ids=['U-1001'])
```

处理顺序：

1. 本进程请求 Go 生成计划。
2. Go 对该 SPL 返回 `requires entity-call`，不给出表名或数据库地址。
3. 本进程读取 `model/`：订单对象对应订单记录，记录位于 MySQL `commerce.t_order`，查找字段为 `user_id`。`U-1001` 进入参数，不写入 SQL 文本。密码引用为 `secret://COMMERCE_MYSQL_PASSWORD`。
4. `mode=plan` 在此结束。
5. `mode=data` 从环境变量读取密码，经 `aiomysql` 连接 YAML 中的地址。未安装驱动或未配置密码则失败。
6. 去掉模型未声明的列。列名和字段名不一致时，按 `fields_mapping` 改回字段名再投影。订单记录没有脱敏标签。用户资料的 `name` 标了 `pii.name`，「张三」返回为「张*」。只有标了 `pii.phone`、`pii.email` 或 `pii.id_card` 的字段才会按对应规则处理。

指标和日志在 Go 已生成对应计划时，由本进程按计划中的地址执行。该地址须列入 `ALLOWED_HTTP_HOSTS`，相关模型须已导入 Go。

## 4. 正式使用

### 4.1 编写本企业模型

按 commerce 示例保留五类元素，不要合并成随意命名的单个文件：

| 元素 | 内容 |
|---|---|
| `entity_set` | 业务对象 |
| `event_set` | 一行的字段。需要脱敏的字段设置 `tags.classification` |
| `storage` | 地址、库名、表名、账号。密码只写 `credential_ref: secret://某个名字`。MySQL 未写 `username` 时用 `readonly` |
| `data_link` | 对象对应哪一个数据集 |
| `storage_link` | 字段对应哪一列 |

对象图需要表达「用户包含订单」时，另加 `entity_set_link`。按用户标识查订单时，在 storage 上写 `lookup_field`。只有表上确实存在租户列时才写 `tenant_field`；只有接口声明了租户头时才写 `tenant_header`。本进程不会默认追加 `tenant_id` 条件。

### 4.2 启动开源服务

每次查询都会先访问 Go。开源服务不在本目录，需要单独检出 `alibaba/UnifiedModel`，在该仓库根目录启动：

```text
go run ./cmd/umodel-server --addr :8080
```

此状态下可以查询本目录 `model/` 中的业务对象，对象图中还没有这些对象。

需要对象图时，Go 只读取 `--import-root` 允许的目录，默认是进程工作目录。`umctl` 把路径交给 Go，由 Go 在本机读取，不会上传文件。路径必须位于 import root 内。示例：

```text
go run ./cmd/umodel-server --addr :8080 --import-root <umodel-assistant-py 的绝对路径>
go run ./cmd/umctl --addr http://127.0.0.1:8080 workspace create demo
go run ./cmd/umctl --addr http://127.0.0.1:8080 umodel import demo --path <model 目录的绝对路径>
```

`--quickstart` 会装入开源示例，不能代替上述导入。

### 4.3 运行本进程

在运行 Python 的环境中设置：

| 变量 | 作用 |
|---|---|
| `UMODEL_ADDR` | Go 地址，默认 `http://localhost:8080` |
| `UMODEL_WORKSPACE` | 工作区，默认 `demo`。工具参数留空时用这个值；写成别的值会被拒绝 |
| `UMODEL_TIMEOUT` | 访问 Go 的超时秒数，默认 `30` |
| `COMMERCE_MYSQL_PASSWORD` 或企业自己的密钥名 | 与 `secret://` 后面的名字一致。示例账号名是 `readonly` |
| `ALLOWED_HTTP_HOSTS` | HTTP、Prometheus、Elasticsearch、ClickHouse 的 `主机:端口`。不约束 MySQL；MySQL 使用 YAML 的 `endpoint` |
| `MAX_SQL_LIMIT` | 单条 SQL 最多返回的行数，默认 `1000` |
| `ENABLE_AUDIT_LOG` | 默认开启。设为 `0` 或 `false` 则不写审计日志 |
| `SECRET_PROVIDER_TYPE` | 保持 `env`。`vault` 和 `kms` 当前会失败 |
| `UMODEL_AUTH_MODE` | `dev_header` 仅用于开发。默认 `deny`，其他取值也会按 `deny` 处理 |
| `UMODEL_DEV_USER`、`UMODEL_DEV_TENANT` | 仅 `dev_header` 使用，从进程环境读取 |

MySQL 需要另行安装 `aiomysql`。用户 REST 的默认白名单是 `127.0.0.1:8001`。

开发身份示例：

```powershell
$env:UMODEL_AUTH_MODE = "dev_header"
$env:UMODEL_DEV_USER = "dev"
$env:UMODEL_DEV_TENANT = "acme"
python mcp_server.py
```

在 Cursor 或企业 Agent 平台中添加该 MCP 服务，工具名为 `query_spl_execute`。

上线前用只读账号对预发库执行一次 `mode=data`，并核对 stderr 里是脱敏后的语句和 `secret://` 名称，不出现密码或令牌。`mocks/` 只供测试，不作为生产数据源。

## 5. 尚未完成、需企业生产接入

下列能力在代码中留有位置。未接入时调用失败，不返回示例数据。搜索 `ENTERPRISE_HOOK` 可定位前三项。

| 能力 | 现状 | 接入位置 |
|---|---|---|
| 员工身份 | 只有 `deny` 与开发用 `dev_header`，没有 OIDC、JWT 或 mTLS | `auth_context.py`；新模式还须在 `config.py` 中放行 |
| 密钥中心 | Vault、KMS 未实现 | `secret_resolver.py` |
| 集中审计 | `push_remote` 在接入 Kafka 或 SLS 之前失败。当前只有本进程日志 | `audit_logger.py` |
| 按调用方授权 | 已登录用户可以读取模型包中的对象，没有按人、按对象的授权策略 | 需在 `policy.py` 之上增加企业策略 |
| 行级范围 | 仅当 storage 声明 `tenant_field` 时写入 SQL 条件 | 模型与策略一起设计 |
| 服务形态 | 单进程标准输入输出，没有独立 REST 门面、限流、配额或高可用 | 部署层 |
| 运行时实体 | 不向 Go 的 EntityStore 写入在线实体，对象图不会自动出现业务实例 | 若业务需要，另行同步 |
| 云上日志与 Prometheus | 没有 SLS、`aliyun_prometheus` 执行器 | 使用这些存储时再增加执行器 |
| 跨数据源 Join | 未实现。关联应先落在数仓或业务服务中 | 不在本进程内临时拼接 |
| 一个数据集多个存储 | 多于一条 `storage_link` 即报错，未使用计划中的 `storage_*` 选择 | 有该需求时再扩展 |

云端控制面、阿里云多租户产品和内部前端不在本目录范围内，也不应从本仓库推断其接口。开源侧仍未提供、且本目录有意不重写的部分，见《UModel 开源范围与自行建设说明》。

## 6. 调用失败条件

| 条件 | 结果 |
|---|---|
| 未设置 `UMODEL_AUTH_MODE=dev_header`，或未设置 `UMODEL_DEV_USER` | `unauthenticated` |
| `secret://` 在环境中没有值 | `not_configured` |
| `SECRET_PROVIDER_TYPE` 为 `vault` 或 `kms` | `not_configured` |
| 未知方言、空壳计划、计划缺少地址 | 对应错误，不返回空列表 |
| URL 不在白名单，或指向元数据、链路本地地址 | `ssrf` |
| Go 不可达 | `go_unreachable` |
| MySQL、HTTP、PromQL、Elasticsearch 或 ClickHouse 请求失败 | `storage_error` |
