# 招聘流程管理系统 (RMS) MVP 需求说明书 (spec.md)

> 本文档为业务视角需求说明。凡与仓库最高准则冲突时，以 `AGENTS.md` 为准；本文已与 `AGENTS.md` §3 硬性约束对齐。

## 一、 业务目标与需求（做什么）

我们需要搭建一个简易、高效的招聘流程管理看板（MVP 版），用于直观展示和管理候选人从投递到录用 / 淘汰的全生命周期状态流转。

### 1.1 核心数据对象（候选人）

系统核心管理对象为**候选人（Candidate）**。主表字段软冻结为以下 **8** 项（禁止改名、删除、修改类型或语义；本次 MVP 不得擅自扩展未声明业务字段）：

| 字段 | 含义 |
| --- | --- |
| ID | 唯一标识 |
| 姓名 | 候选人姓名 |
| 电话 | 联系电话 |
| 邮箱 | 联系邮箱 |
| 应聘职位 | 应聘岗位 |
| 当前状态 | 五态之一（见下） |
| 来源渠道 | 候选人来源 |
| 创建时间 | 创建时间（ISO 8601） |

### 1.2 看板界面呈现

前端看板按固定顺序划分为 **5 列**，对应候选人的五种状态：

1. **已投递**（APPLIED）
2. **筛选中**（SCREENING）
3. **面试中**（INTERVIEWING）
4. **已录用**（HIRED）
5. **已淘汰**（REJECTED）

候选人卡片呈现在其当前状态对应的列中。

### 1.3 状态流转规则（五态线性，无回退）

候选人状态流转必须严格遵守受控状态机，**禁止越级跳跃，禁止任何形式的回退**：

| 当前状态 | 允许流转到 |
| --- | --- |
| 已投递（APPLIED） | 筛选中（SCREENING）、已淘汰（REJECTED） |
| 筛选中（SCREENING） | 面试中（INTERVIEWING）、已淘汰（REJECTED） |
| 面试中（INTERVIEWING） | 已录用（HIRED）、已淘汰（REJECTED） |
| 已录用（HIRED） | —（终态，禁止任何变更） |
| 已淘汰（REJECTED） | —（终态，禁止任何变更） |

补充业务规则：

* **任意非终态皆可转为已淘汰（REJECTED）**：已投递、筛选中、面试中均可直接淘汰。
* **录用必须走完面试**：只有处于「面试中」才能进入「已录用」；禁止从已投递 / 筛选中直接录用。
* **终态不可变**：一旦进入已录用或已淘汰，禁止任何进一步状态变更。

### 1.4 交互要求

* 卡片上的操作按钮**仅根据后端返回的「可用动作」渲染**；前端禁止自行实现或硬编码流转判定。
* 用户点击动作后，系统向后端提交状态变更请求；界面依据响应结果即时同步卡片所在列。
* 合法变更成功后界面刷新到新状态列；非法变更由后端拒绝，前端展示错误信息且不移动卡片。

## 二、 约束与边界红线（不许动什么）

为确保 MVP 轻量可控，本次开发必须严格遵守以下红线：

1. **本地数据库边界**：候选人主数据使用 Compose 管理的 MySQL 8 持久化；只允许连接项目声明的本地实例。schema 必须通过版本化迁移建立，禁止应用启动时隐式建表或重置数据。
2. **状态校验必须统一收敛**：合法性校验只能走统一的状态机校验能力；后端任何修改候选人状态的路径都必须经此校验。前端按钮仅为操作触发器，**绝对禁止**在前端硬编码流转规则，或绕过校验直接改数据。
3. **主表字段软冻结**：候选人主表仅限上述 8 个基础字段；禁止改名、删除、改类型 / 语义；本次 MVP 禁止擅自扩展未声明业务字段（如打分、评语、简历路径等）。
4. **非法流转错误约定**：非法状态跳转一律拒绝修改，返回 **HTTP 409**，错误体为 `INVALID_TRANSITION` 约定格式（含明确可读的 message）。
5. **无额外未经许可依赖**：严格基于项目预设技术栈（React 18 + Vite / Express + TypeScript / Jest），不安装未经许可的重型 UI 组件库或全局状态管理库。
6. **分层边界**：业务规则不得写在路由回调或 React 组件中；数据库访问只能位于 repository 层，路由不得绕过 service 层。

## 三、 交付与验收标准（怎么算完成）

只有同时满足以下标准，本需求才算正式完成交付：

1. **后端单元测试全绿**
   * 必须针对状态流转校验能力编写完整的 Jest 单元测试。
   * 测试用例须覆盖全部**合法跳转**（含各非终态 → REJECTED，以及 APPLIED → SCREENING → INTERVIEWING → HIRED 的逐步推进）与典型**非法跳转**（如 APPLIED → HIRED、SCREENING → HIRED、HIRED → 任意状态、REJECTED → 任意状态、越级与回退等）。
   * 在仓库根目录运行 `npm test` 必须全部通过。

2. **非法跳转防御生效**
   * 当收到非法状态更新请求时，后端必须拒绝修改，返回 **HTTP 409**，错误码为 **`INVALID_TRANSITION`**，并附带明确的错误说明。

3. **前后端交互联调通过**
   * 启动前后端服务后，浏览器打开看板可正常渲染 **5 列**候选人卡片。
   * 仅展示后端返回的可用动作；点击后合法请求成功（如 HTTP 200），卡片移动到新状态列；非法请求得到 409 且卡片位置不变。
